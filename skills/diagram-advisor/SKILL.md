# 绘图顾问

先理解用户希望通过图回答的问题，再推荐图类型，等用户选定后使用 `drawio-skill` 生成可编辑图。适用于技术和业务场景，跟随用户的语言交流。

## 1. 分析问题

结合当前对话和用户提供的资料，简要说明：要回答的核心问题、目标读者、内容范围，以及关键对象与关系。区分有来源的事实和待确认的假设。

资料足够时直接推荐。只有缺失信息会改变图类型或主要内容时，才问一个聚焦的问题；不要把受众、风格、尺寸等变成固定问卷。涉及代码或文档时先读取相关来源，不能凭名称虚构调用关系。

## 2. 推荐候选

给出 2～4 个适合当前问题的候选，用简短表格列出「图类型、针对这个问题会画什么、优势与局限」，标出一个推荐项并说明理由。候选应体现不同的观察角度；确实只有一种合适时说明原因，不凑数量。

按表达目的选择，不固定套用某几种图：

| 要回答的问题 | 可考虑的图类型 |
| --- | --- |
| 经过哪些步骤、在哪里分支 | 流程图、活动图 |
| 谁负责哪一步、如何交接 | 泳道图、BPMN |
| 多方按什么顺序交互 | 时序图 |
| 有哪些状态、什么条件触发切换 | 状态图 |
| 模块职责、依赖或部署位置 | 架构图、组件图、部署图 |
| 数据从哪里来、如何处理和流转 | 数据流图 |
| 实体有哪些关联与约束 | ER 图、类图 |
| 概念如何分层组织 | 思维导图、层级图 |
| 事件顺序或工作周期 | 时间线、甘特图 |

以上是选图线索，不是每次都要展示的菜单。复杂问题可推荐组合图，说明各图分别回答什么；不要把不同视角硬塞进一张图。

## 3. 等待选择

展示候选后，请用户选择一种或组合几种，然后等待回复。此阶段只输出分析和文字方案，不生成 `.drawio`、Mermaid 草图、预览图，也不启动绘图工具。

- 用户明确选定候选，或明确表示采用唯一标出的推荐项，即可进入绘图。
- 用户只继续讨论、提出疑问或补充资料时，更新分析与候选，继续等待选择。没有回复不能视作选择。
- 用户在当前请求或前文已明确指定图类型和绘制范围时，沿用已有选择，不重新列候选要求确认。显式要求先比较时仍先比较。
- 用户改选图类型或要求组合图时，以最新明确选择为准。

## 4. 交给 drawio 绘制

**必需下游技能：`drawio-skill`。** 选定后，从当前技能目录清单定位并读取它的 `SKILL.md`；作为 Claude Code 插件安装时，它位于 `${CLAUDE_PLUGIN_ROOT}/../../drawio-skill/*/skills/drawio-skill/SKILL.md`（占位符未被替换说明不是插件安装，忽略此路径）。按其中与任务相关的绘制、布局和校验流程执行，不在本技能复制 XML 或工具命令。

交接时沿用对话中的绘图简报：目的与读者、已选图类型、范围、关键节点与关系、资料来源及待确认假设、用户指定的风格和输出位置。多图分别说明视角和共同对象，保持命名一致。

默认交付可编辑 `.drawio`，输出目录及导出格式遵循用户要求和当前工作区规则。选型确认后直接完成绘制与校验，不再次要求批准同一选择。对影响图意的事实缺口先澄清，其余排版细节自行处理。

若找不到 `drawio-skill`，保留已确认的绘图简报，说明缺少依赖并请求提供位置；不要宣称已经绘制，也不要擅自换绘图工具。交付时链接实际生成的文件，简述它回答的问题，并如实说明未完成的校验。
